# 工具、插件、外部操作与协作

## 能力路由原则

复杂项目的 Skill 选择、实际加载、阶段切换和缺失能力处理，按 [自动技能路由.md](自动技能路由.md) 执行。下面的能力族仅用于候选搜索，不替代当前会话的技能清单。

选择最窄、当前可调用且直接服务于用户结果的能力。先检查当前工具列表和已加载技能，再选择候选路线；同一结果优先使用更具体的原生能力，不叠加互相抢占的宽泛技能。

区分 `read`、`draft`、`write`、`publish`、`send`、`schedule` 和 `delete`。技能可路由不等于插件已安装，能力可用不等于拥有外部写入权限。当前会话的能力清单优先于本文中的类别示例。

常见类别：

| 结果 | 优先能力族（若当前可用） |
|---|---|
| 代码计划、TDD、调试、审查 | `superpowers:*` |
| Web、React、组件、Stripe、Supabase | `build-web-apps:*` |
| 产品审计、设计、图片/URL 到代码 | `product-design:*` |
| 数据、KPI、报告、仪表板、可视化 | `data-analytics:*` |
| Word、PDF、表格、演示 | `documents:*`、`pdf:*`、`spreadsheets:*`、`presentations:*` |
| Google Drive 生态 | `google-drive:*` |
| Figma / Canva | `figma:*` / `canva:*` |
| 网站托管 / 视频构成 | `sites:*` / `hyperframes:*` |
| 图像与媒体生成/编辑 | `imagegen` 或当前可用的媒体专项能力 |
| Codex 任务、工作区、自动化和界面 | 对应的 Codex app 工具 |

只有当用户明确点名某个插件、当前工具搜索已用尽、该插件出现在当前推荐列表中且安装是完成任务所必需时，才建议安装。不能因未来可能有用而安装。

## 外部操作

准备和变更分开：先读取、起草、预览、确认目标和副作用，再执行真正的外部写入。

| 类型 | 默认处理 |
|---|---|
| Read | 在请求范围内查看并引用 |
| Draft/Preview | 可生成内容或 payload，不发送、不发布 |
| Reversible write | 执行前核对目标、范围、权限和结果 |
| Irreversible/delete | 精确确认对象，优先可恢复方案 |
| Send/publish/share | 核对收件人、可见范围、内容、时间和通知 |
| Schedule/monitor | 核对时区、频率、停止条件和通知策略 |

预检账号、工作区、项目、文件、记录集合、目标对象、收件人、频道、公开范围、版本、时间、时区、通知、重试行为、幂等性和撤销方式。先查找同名或同目的的已有对象，避免重复创建。

工具返回“调用成功”只证明请求被接受。还应核对返回状态、对象标识、实际可见效果、权限、通知和重复风险。目标不明确、授权缺失、权限异常、内容超范围、不可逆目标未确认、结果不确定、重试可能产生重复副作用或凭据/隐私有风险时停止。

## 自动化

优先更新已有自动化，不重复创建。保留用户的通知偏好；心跳监控在状态未变化或不可行动时保持安静，只在有意义变化、完成、失败或需要用户行动时通知。记录时区、频率、停止条件、下一次运行时间和修改/删除方式。

## 线程与并行协作

只有真正独立、输入输出清楚、依赖低、可隔离副作用且有明确合并方式的工作才并行。否则保持单线程。

每个子任务说明目标、背景、允许读取的资源、允许写入的范围、禁止的外部动作、成功标准、返回格式和阻塞报告方式。不要复制无关历史。主任务负责权限、合并和按原始成功标准重新验证；子任务完成不等于主任务完成，冲突结论必须保留并解释。

创建新 Codex 任务、发送消息、交接、归档或调度只在用户意图明确且工具允许时执行。等待使用有界机制和返回的游标/主机标识；不要重复轮询未变化状态，只在完成、失败、需要输入或计划实质变化时更新。

## 外部操作收尾

报告实际动作、目标、状态、对象标识或安全链接、通知与可见范围、未确认事项及回滚/停止路径。不要暴露凭据或隐私。
